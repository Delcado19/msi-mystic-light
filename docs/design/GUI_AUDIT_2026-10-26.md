## Identity and direction

The product's own material: physical LED positions, controller headers, wire order,
recognizable component artwork, gaming peripherals, spatial sampling, layered light
fields, masks, channel clocks and physical output. The main job is to compose light
and see how it lands on a real setup.

- Layout asks: where does each component sample the light field?
- Effects asks: what does the composition produce, and what changes this layer?
- Hardware asks: which device/header is configured, connected and receiving output?
- Component editor asks: which LED occupies each position and wire address?

Idea: three physical light rails become the identity mark and selection language;
the actual lighting composition remains the visual signature.

Taste draw returned True-black flat and Data terminal. Selected Data terminal,
seed 1383183833, for long sessions, stable numbers and consistent selection.
Proposed adaptations: preserve labeled workspaces, the native system font and cyan
instead of the dealt blue. This is a direction, not a claim of implemented tokens.
Lighting gradients and alpha checkerboards are actual content, not decoration.
UI Pro Max's broad gaming search proposed a 3D marketing showcase; rejected that
output because this is a native editor. Apply only its relevant interaction guidance.

Proposed palette: ground #111214, surface #1b1d21, raised #24272d, text #f1f3f5,
secondary #afb4bd, cyan #55deff. Keep saturated RGB on lighting previews. Reserve
green/amber/red plus text for output status. One selection accent; remove competing
violet states and equally bright outlines on every button. Tight 4-6 px corners,
consistent icons, visible focus and 32-36 logical-pixel controls support the gaming
direction. No glow, glass, animated borders or display font in input fields.

Keep Lighting Studio as the working name. Show its mark/name in the client area;
move MSI standalone identity into hardware/support information as modules expand.
See lighting-studio-brand-concepts.svg: Channel mark, Light routing, Canvas beam.
Prefer Channel mark, subject to 16/24/32 px, monochrome and distinctiveness checks.
These are unapproved drafts; trademark checks and app-icon exports are outstanding.

## Color picker

Current picker already offers visual selection, exact RGB, Hex, custom colors and
a screen eyedropper. The problem is interruption and fragmentation, not missing
basic color capability. It is not the preferred primary workflow for this editor.

Propose an anchored hue strip plus saturation/value square, integer HSV, Hex,
previous/current swatches, recent/project colors and the existing eyedropper.
RGB details remain optional. A rectangular field fits the inspector better than a
large wheel. Share the editor across source, gradient, cycle and native colors.
Keep spatial gradient stops distinct from temporal palette stops. Layer opacity
stays outside the picker. Per-stop alpha, if exposed, needs its own clear scope.

Preview continuously; one drag is one undo action. Escape/Cancel restores the
previous color/frame. Preserve keyboard focus and screen bounds. This proposal
does not require a third-party picker library or claim one was benchmarked.

Adobe documents HSB hue and RGB conventions:
https://helpx.adobe.com/photoshop/desktop/adjust-color/choose-colors/choose-colors-with-the-adobe-color-picker.html

## Integer scales

Do not set every control to zero decimals: a 0..2-second trail would have only
three values; a 0..1 crop would become unusable. Convert display units instead.

| Control | Current model | Proposed normal display |
| --- | --- | --- |
| Layer transparency | 0..100 inverse coverage | Opacity 0..100%, step 1; 100 means fully visible |
| Rotation/hue rotation | -360..360 degrees/sec | Integer degrees/sec; centered, marked zero |
| Pulse/breathe/palette rate | 0..10 cycles/sec | 0..600 cycles/min, integer, 0 Off; emphasize slow range |
| Trails | 0..2 seconds | 0..2000 ms; pointer step 10, numeric step 1 |
| Drift X/Y | -500..500 px/sec | -500..500 px/s, step 1 |
| Zoom amplitude | 0..90 percent | 0..90%, step 1; preserve renderer limit |
| Warp | 0..100 pixels | 0..100 px, step 1 |
| Particle count | 1..400 | 1..400, step 1 |
| Particle speed | 0..500 maps to 0..2.5 cycles/sec | 0..150 cycles/min, step 1; pattern-specific motion |
| Particle radius | 1..40 pixels | 1..40 px, step 1; call it Radius |
| Particle seed | 0..1000000 | Integer input plus Randomize, no huge slider |
| Brush diameter | 1..320 pixels | 1..320 px, step 1 |
| Brush hardness/opacity | 0..100 percent | 0..100%, step 1 |
| Mask gray | 0..255 | Reveal 0..100%; Black/White presets; retain exact alpha internally |
| Crop | Normalized 0..1 | Source-pixel integers and visual crop; retain subpixel legacy values |
| Position/size/angle | Large floating-point ranges | Integer px/degrees normally; preserve legal bounds and exact saved transforms |
| Channel clock | 0..10 multiplier | 0..1000%, step 1; 100% normal |
| Channel offset | 0..86400 seconds | Whole ms normally; time input for long offsets, no huge linear slider |
| Native speed | Indices 0..2 | Three named choices, index order verified per device |
| Native brightness | Indices 0..5 | Six discrete levels; no fake continuous hardware precision |

Cycles/min are not BPM/music synchronization. Useful rate marks: 0, 6, 15, 30,
60, 120, 600, plus exact entry. Avoid an unexplained universal Speed 0..100 that
hides unrelated units. Existing 0.25 cycles/sec becomes a clear 15 cycles/min.

Opening, selecting, refreshing or saving an unchanged project must never round
stored values. Off-grid legacy values need an approximation indicator and exact
inspection; only explicit editing replaces them with the new integer scale.
Preserve combined pulse/breathe and hue/palette settings. UI rounding is not a
schema migration. One gesture produces one undo action. Reset default differs
from Off. Keyboard control must reach min/max/zero/default.

Microsoft recommends sliders for relative adjustment, numeric input for exact
values, meaningful steps, visible ranges and immediate feedback:
https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/slider

## Motion opportunities

Existing preview already carries substantial motion. No extra animation dependency
is justified. Values below are proposals, not tested Qt timing measurements.

| Location | Current state | Purpose/frequency | Proposal |
| --- | --- | --- | --- |
| New color popover, ColorEditor trigger (StudioWidgets.cpp:192) | Blocking dialog | Spatial consistency; occasional mouse opening | Opacity 0..1, 140 ms OutCubic; fixed anchor. Reduced motion/keyboard: immediate. |
| Save/connect confirmation | Text update | Feedback; occasional | Opacity 0..1, 120 ms OutCubic, no translation/bounce. Reduced motion: immediate. Critical errors persist. |
| Disclosure chevron (StudioWidgets.cpp:127) | Instant arrow swap | State indication; occasional mouse expansion | Rotate 0..90 degrees, 140 ms OutCubic. Content layout updates immediately. Reduced motion/keyboard: immediate. |

Rejected: slider/color drag, transform handles and mask strokes (continuous precise
input must follow the pointer); workspace/tool shortcuts (frequent keyboard use);
dock resizing and hardware canvas (render/layout cost); logo/border loops
(decorative distraction); layer reorder bounce/stagger (order must stay legible).

Verdict: very little additional motion. Highest leverage is live color feedback,
not its entrance animation. Reduced UI motion must not stop authored lighting.

## Implementation order and acceptance

1. Units, names and integer display mappings. Prove legacy load/save/refresh keeps
   exact values; test zero, range ends, off-grid values and gesture undo.
2. Source/Motion ownership, layer creation and bulk scope. Preserve effects and
   shortcuts; active editing target remains obvious with Inspector hidden.
3. Shared live picker. Prove Escape rollback, drag undo, typed Hex/RGB/HSV,
   black/white hue handling and palette-stop selection.
4. Graphite/cyan identity, toolbar hierarchy and chosen mark. Compare real projects
   at wide/minimum sizes and 125/150/200% scaling; keyboard and focus checks.
5. Add only motion that still helps; benchmark preview/input cost before acceptance.

Top three improvements: meaningful integer scales, live shared color editing and
stable Source/Motion ownership. Branding complements those changes.

No numerical usability score: screenshots/code do not establish user satisfaction.
Hardware-connected flows, assistive technology, animation timing and performance
remain unverified. No implementation, packaging, commit or publication performed.
