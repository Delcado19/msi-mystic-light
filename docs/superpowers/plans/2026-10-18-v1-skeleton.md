# Standalone Lighting App — v1 Skeleton Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a working v1 skeleton that drives the user's MSI MPG B850 Edge TI WiFi motherboard (VID:PID `0DB0:0076`) over raw USB HID, with per-channel choice between native firmware modes and custom software-rendered per-LED effects, running as a Windows tray app with autostart.

**Architecture:** A pure-logic core (MSI wire-protocol encoders, Component/Channel device model, Canvas render loop, Settings persistence) fully unit-tested against fake HID/effect doubles with zero hardware dependency, wrapped by a thin Qt tray-app shell and a real hidapi-backed transport that only gets exercised manually, under the project's explicit safety rule, against the real board.

**Tech Stack:** C++17, CMake, Qt6 (Widgets + Test modules, LGPL dynamic linking), hidapi, nlohmann::json or Qt's own `QJsonDocument` for Component/Settings serialization (Qt is already a dependency — use `QJsonDocument`, no new JSON library).

**Spec:** `docs/superpowers/specs/2026-10-18-standalone-lighting-app-design.md`
**Protocol reference:** `docs/MB_800_HID_PROTOCOL.md`

## Global Constraints

- All code, comments, commit messages, and docs in English, regardless of chat language (standing project rule).
- No AI co-authorship credit in any commit.
- No runtime dependency on MSI Center, LEDKeeper2, OpenRGB, or SignalRGB — reference material only, never linked/loaded at runtime.
- Project license: GPL-2.0-or-later (public release is a real possibility; matches OpenRGB).
- Qt used under LGPL terms: dynamic linking only, no static Qt link.
- Never send an unconfirmed/untested byte sequence to the real board without first showing the exact bytes and getting explicit plain-language human confirmation (carried over from this session; see Task 12, Step 4).

## Review Focus

- **MSI board not connected/unplugged** (at app startup or mid-session): driver calls must return failure gracefully, never throw or crash. → `Task 6`.
- **Settings file missing or corrupted on first run or after a manual edit**: app must fall back to defaults, never crash, since "restores last-applied config on launch" is a stated goal. → `Task 9`.
- **Hand-edited Component JSON with inconsistent array lengths** (`ledCoordinates`/`ledNames`/`ledMapping` not matching `ledCount`): Components are explicitly human-editable per the design doc, so a malformed file is an expected real input, not a hypothetical. → `Task 4`.
- **Adding a Component to a Channel that would exceed the channel's LED limit**: the design doc states the device driver chain has a limit; this needs its own concrete test, not just an interface comment. → `Task 5`.
- **A HID feature-report send failing mid-session** (device unplugged while running, OS reports failure): the render loop must keep ticking the other channels, not abort the whole frame. → `Task 8`.

Exact types and byte layout (from `docs/MB_800_HID_PROTOCOL.md`):

```cpp
struct MsiColor { uint8_t r = 0, g = 0, b = 0; };

enum class MsiLightingMode : uint8_t {
    Off = 0, Wave = 1, Steady = 2, Flame = 3, Breathing = 4, ColorRing = 5,
    Lightning = 6, Recreation = 7, Meteor = 8, Advanced = 9, GodLike = 10
};

// One 16-byte record of report 0x50. Default-constructed = Off, all-black, matches an unused zone.
struct MsiZoneSettings {
    MsiLightingMode lightingMode = MsiLightingMode::Off;
    MsiColor color1{}, color2{}, color3{}, color4{};
    uint8_t colorCount = 1;          // 1-4 active colors (encoded as (colorCount-1) in Option1 bits 0-1)
    bool selectAll = false;          // Option2 bit 7
    bool directionInward = false;    // Option2 bit 6 (false=Out, true=In)
    bool colorSelectionUser = false; // Option2 bit 5 (false=Rainbow, true=User)
    uint8_t brightness = 5;          // Option2 bits 4-2, 0-5 -> 0/20/40/60/80/100%
    uint8_t speed = 0;               // Option2 bits 1-0, 0-2
    uint8_t cycleNum = 30;           // last byte of the record
};

// Builds the full 290-byte report 0x50 payload. zones[i] is the record for
// MsiZoneIndex i (JARGB1=0 ... SelectAll=17), written contiguously starting
// at byte 1 (NO separate header — see docs/MB_800_HID_PROTOCOL.md). Byte 0
// is the report ID (0x50). Byte 289 is the Store flag: `store` true persists
// to board NVRAM, false (the default, and v1's only use) is session-only.
std::array<uint8_t, 290> BuildReport0x50(const std::array<MsiZoneSettings, 18>& zones, bool store = false);

// Area addresses for report 0x51 (big-endian uint16 at bytes 2-3).
enum class MsiGen1AdvArea : uint16_t {
    JRGB1 = 0x0200, JRGB2 = 0x0201,
    JPIPE1 = 0x0300, JPIPE2 = 0x0301, JPIPE3 = 0x0302, JPIPE4 = 0x0303, JPIPE5 = 0x0304,
    JARGB1 = 0x0400, JARGB2 = 0x0401, JARGB3 = 0x0402,
    SelectAll = 0x0600,
    Onboard1 = 0x0700, Onboard2 = 0x0701, Onboard3 = 0x0702, Onboard4 = 0x0703, Onboard5 = 0x0704, Onboard6 = 0x0705,
    JAF = 0x0800
};

// Builds the 727-byte report 0x51 (Gen1_Adv) payload: byte0=0x51, byte1=0x09,
// bytes2-3=area (big-endian), bytes4-5=0x00, byte6=colors.size(), bytes7+ =
// RGB triplets, remainder zero-padded to 727. Throws std::invalid_argument
// if colors.size() > 240.
std::array<uint8_t, 727> BuildReport0x51(MsiGen1AdvArea area, const std::vector<MsiColor>& colors);
```

Bit-packing (pin exactly, this is safety-critical — wrong bits mean wrong bytes to real hardware):
`Option1 = (colorCount - 1) & 0x03`
`Option2 = (selectAll<<7) | (directionInward<<6) | (colorSelectionUser<<5) | ((brightness & 0x07)<<2) | (speed & 0x03)`
Record `i` occupies bytes `[1 + i*16 .. 16 + i*16]` of the 290-byte array, in order: `lightingMode, color1.r, color1.g, color1.b, color2.r, color2.g, color2.b, color3.r, color3.g, color3.b, color4.r, color4.g, color4.b, Option1, Option2, cycleNum`.

    virtual bool isOpen() const = 0;
    // report must already include the report ID as report[0].

};

// tests/hid/FakeHidDevice.h — test double, no .cpp (header-only, test-only).
class FakeHidDevice : public IHidDevice {
public:
    bool open(uint16_t, uint16_t) override { opened_ = true; return openSucceeds; }
    void close() override { opened_ = false; }
    bool isOpen() const override { return opened_; }
    bool sendFeatureReport(const uint8_t* report, size_t length) override {
        sentReports.emplace_back(report, report + length);
        return sendSucceeds;
    }
    bool openSucceeds = true;
    bool sendSucceeds = true;
    std::vector<std::vector<uint8_t>> sentReports; // every report sent, in order
private:
    bool opened_ = false;
};

**Interfaces:**

```cpp
enum class ChannelMode { Canvas, Native };

// Mirrors MsiZoneSettings; kept separate so callers of the driver don't
// need to know the Option1/Option2 bit-packing, only plain fields.
struct NativeModeSettings {
    MsiLightingMode lightingMode = MsiLightingMode::Steady;
    MsiColor color1{}, color2{}, color3{}, color4{};
    uint8_t colorCount = 1;
    bool selectAll = false;
    bool directionInward = false;
    bool colorSelectionUser = true;
    uint8_t brightness = 5;
    uint8_t speed = 0;
    uint8_t cycleNum = 30;
};

class MsiMotherboardDriver {
public:
    explicit MsiMotherboardDriver(IHidDevice& hid);

    // Fixed channel topology for the MPG B850 Edge TI WiFi (MS-7E62), per
    // docs/MB_800_HID_PROTOCOL.md: "JARGB1"/"JARGB2"/"JARGB3" (<=120 LEDs
    // each, zone indices 0/1/2, Gen1Adv areas JARGB1/JARGB2/JARGB3),
    // "EZConnector" (<=120 LEDs, zone index 4 = IO Cover... see note below),
    // "IOShield" (11 LEDs, zone index 4, Gen1Adv area JPIPE1),
    // "JRGB1" (1 LED, zone index 9, native-mode only - not addressable
    // per-LED, so Canvas mode is unsupported for this one channel and
    // setChannelMode("JRGB1", Canvas) returns false).
    static std::vector<Channel> createDefaultChannels();

    // Returns false (no-op) for an unknown channel name, or for "JRGB1"
    // with mode == Canvas (not per-LED addressable).
    bool setChannelMode(const std::string& channelName, ChannelMode mode);
    ChannelMode channelMode(const std::string& channelName) const;

    // Native mode only. Updates this channel's record in the internal
    // 18-zone state (so other zones' last-sent settings are preserved)
    // and sends the full report 0x50. Returns false without sending if
    // !hid.isOpen(), channelName is unknown, or channelMode(channelName)
    // != Native.
    bool setNativeMode(const std::string& channelName, const NativeModeSettings& settings);

    // Canvas mode only. Sends report 0x51 for this channel's Gen1Adv area.
    // Returns false without sending if !hid.isOpen(), channelName is
    // unknown, or channelMode(channelName) != Canvas.
    bool pushCanvasColors(const std::string& channelName, const std::vector<MsiColor>& colors);

private:
    IHidDevice& hid_;
    std::array<MsiZoneSettings, 18> zoneState_{}; // last-sent 0x50 state for ALL zones
    std::map<std::string, ChannelMode> channelModes_;
};

struct ChannelAssignment {
    ChannelMode mode = ChannelMode::Canvas;
    std::shared_ptr<IEffect> effect;        // used when mode == Canvas
    NativeModeSettings nativeSettings;      // used when mode == Native
};

class Canvas {
public:
    Canvas(MsiMotherboardDriver& driver, std::map<std::string, Channel>& channels);

    // Sets/replaces the assignment for a channel. Marks the channel's
    // native-mode settings as pending-send (see tick()) if mode == Native.
    void setAssignment(const std::string& channelName, ChannelAssignment assignment);

    // One render tick at elapsedMs since some external reference time:
    // - Canvas-mode channels: for every LED index in channel.colors(),
    //   looks up ledPosition(index), samples assignment.effect->colorAt(x,y,elapsedMs),
    //   writes it via channel.setColor(index, ...), then calls
    //   driver.pushCanvasColors(channelName, channel.colors()) once per channel.
    // - Native-mode channels: calls driver.setNativeMode(channelName, assignment.nativeSettings)
    //   ONLY if that channel is still marked pending-send (i.e. only the
    //   first tick after setAssignment() last touched it) — not every tick.
    // Continues to the next channel if any single channel's driver call
    // returns false; never throws.
    void tick(int64_t elapsedMs);

private:
    MsiMotherboardDriver& driver_;
    std::map<std::string, Channel>& channels_;
    std::map<std::string, ChannelAssignment> assignments_;
    std::map<std::string, bool> nativeModePending_;
};
```
